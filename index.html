Dicionário de Dados do Modelo Conceitual

Modelo apresentado no diagrama “Conceptual model - BRMW”.

1. Modelo conceitual

O modelo representa um processo de vendas, entrega, pagamento, emissão de nota fiscal e produção, envolvendo as entidades Cliente, Representante, Pedido, Pagamento, Entrega, Nota Fiscal, Produto, Material, Fornecedor, Produção e Embalagem.

Entidade Relaciona-se com Relacionamento / Cardinalidade
CLIENTE PEDIDO FAZ — Cliente (0,n) / Pedido (1,n)
REPRESENTANTE CLIENTE CADASTRA — Representante (0,n) / Cliente (1,n)
PEDIDO ENTREGA GERA — Pedido (0,1) / Entrega (1,1)
PEDIDO PRODUTO POSSUI — Pedido (0,n) / Produto (1,1)
PAGAMENTO PEDIDO POSSUI — Pagamento (1,1) / Pedido (0,1)
FORNECEDOR MATERIAL FORNECE — Fornecedor (0,n) / Material (0,n)
MATERIAL PRODUTO É FEITO COM — Material (0,n) / Produto (1,n)
MATERIAL PRODUÇÃO É UTILIZADO — Material (0,n) / Produção (1,n)
PRODUTO PRODUÇÃO É PRODUZIDO EM — Produto (0,n) / Produção (1,1)
PRODUÇÃO EMBALAGEM UTILIZA — Produção (1,n) / Embalagem (0,n)

LEITURA

Entidade LEITURA
CLIENTE Representa o cliente cadastrado no sistema, reunindo informações de identificação, endereço, unidade federativa e contato para permitir seu relacionamento com pedidos e representantes.
REPRESENTANTE Representa o responsável pelo atendimento e cadastro de clientes, mantendo seus dados de identificação e contato para o relacionamento comercial.
PEDIDO Representa uma solicitação de compra realizada por um cliente, registrando seu identificador, valor, situação e data, além de permitir o relacionamento com produtos, pagamento e entrega.
PAGAMENTO Representa o registro financeiro associado a um pedido, contendo a data, o valor e a situação do pagamento realizado.
ENTREGA Representa o processo de entrega associado ao pedido, contendo informações de data, situação, motorista, caminhão e código de rastreamento.
NOTA_FISCAL Representa o documento fiscal emitido para registrar a operação comercial, contendo número, série, status, data de emissão, valor total e chave de acesso.
PRODUTO Representa o produto comercializado ou produzido pela empresa, identificado por código próprio e EAN, com nome, unidade de comercialização e descrição.
MATERIAL Representa os materiais utilizados na composição ou fabricação dos produtos e nos processos de produção, mantendo informações de identificação, unidade e estoque mínimo.
FORNECEDOR Representa a empresa ou entidade responsável pelo fornecimento de materiais, mantendo seus dados de identificação, endereço e contato.
PRODUÇÃO Representa uma ocorrência de produção, registrando a quantidade produzida, seu status, a data de emissão e os relacionamentos com produto, material e embalagem.
EMBALAGEM Representa a embalagem utilizada no processo produtivo, contendo seu tipo, capacidade e material de composição.

3. Dicionário de dados por entidade

CLIENTE

CLIENTE = @ID_CLIENTE + NOME_CLIENTE + CPF + ENDERECO_CLIENTE + TELEFONE_CLIENTE + UF_CLIENTE

LEITURA: @ID_CLIENTE identifica exclusivamente o cliente. Os demais atributos formam seu cadastro básico, registrando nome, CPF, endereço, telefone e unidade federativa.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO
ID_CLIENTE integer Sim PK Identificador único utilizado para distinguir cada cliente cadastrado no sistema.
NOME_CLIENTE varchar(150) Sim — Nome utilizado para identificar formalmente o cliente no cadastro e nos relacionamentos comerciais.
CPF varchar(14) Sim — Documento de identificação fiscal utilizado para identificar o cliente pessoa física.
ENDERECO_CLIENTE varchar(200) Sim — Endereço informado para localização e comunicação com o cliente.
TELEFONE_CLIENTE varchar(20) Sim — Número de telefone utilizado como meio de contato com o cliente.
UF_CLIENTE char(2) Sim — Unidade federativa correspondente à localização do cliente.

REPRESENTANTE

REPRESENTANTE = @ID_REP + EMAIL_REP + NOME_REP + TELEFONE_REP

LEITURA: @ID_REP identifica exclusivamente o representante. Os demais atributos registram seus dados de contato e identificação.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO
ID_REP integer Sim PK Identificador único utilizado para distinguir cada representante cadastrado.
EMAIL_REP varchar(150) Sim — Endereço de e-mail utilizado para comunicação com o representante.
NOME_REP varchar(120) Sim — Nome completo utilizado para identificação do representante responsável pelo atendimento.
TELEFONE_REP varchar(20) Sim — Número de telefone utilizado para contato com o representante.

PEDIDO

PEDIDO = @ID_PEDIDO + PRECO_PEDIDO + STATUS_PEDIDO + DATA_PEDIDO

LEITURA: @ID_PEDIDO identifica exclusivamente o pedido. Os demais atributos registram seu valor, situação e data.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO
ID_PEDIDO integer Sim PK Identificador único utilizado para distinguir cada pedido realizado no sistema.
PRECO_PEDIDO decimal(12,2) Sim — Valor monetário associado ao pedido, utilizado para representar o preço total registrado para a solicitação.
STATUS_PEDIDO varchar(30) Sim — Situação atual do pedido dentro do processo comercial, permitindo acompanhar seu andamento.
DATA_PEDIDO date Sim — Data em que o pedido foi registrado ou realizado pelo cliente.

PAGAMENTO

PAGAMENTO = @ID_PAGAMENTO + DATA_PAGAMENTO + PRECO + STATUS_PAGAMENTO

LEITURA: @ID_PAGAMENTO identifica exclusivamente o pagamento. Os demais atributos registram a data, o valor e a situação do pagamento.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO
ID_PAGAMENTO integer Sim PK Identificador único utilizado para distinguir cada registro de pagamento.
DATA_PAGAMENTO date Sim — Data em que o pagamento foi realizado ou registrado no sistema.
PRECO decimal(12,2) Sim — Valor monetário efetivamente registrado para o pagamento associado ao pedido.
STATUS_PAGAMENTO varchar(30) Sim — Situação do pagamento, utilizada para indicar seu estado dentro do processo financeiro.

ENTREGA

ENTREGA = @ID_ENTREGA + DATA_ENTREGA + STATUS_ENTREGA + NOME_MOTORISTA + ID_CAMINHAO + CODIGO_RASTREIO

LEITURA: @ID_ENTREGA identifica exclusivamente a entrega. Os demais atributos registram quando a entrega ocorre, sua situação, o motorista, o caminhão e o código utilizado para rastreamento.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO
ID_ENTREGA integer Sim PK Identificador único utilizado para distinguir cada entrega registrada.
DATA_ENTREGA date Sim — Data prevista ou registrada para a realização da entrega.
STATUS_ENTREGA varchar(30) Sim — Situação atual da entrega dentro do processo logístico.
NOME_MOTORISTA varchar(120) Sim — Nome do motorista relacionado à execução ou transporte da entrega.
ID_CAMINHAO integer Sim — Identificador do caminhão utilizado no transporte da entrega.
CODIGO_RASTREIO varchar(60) Sim — Código utilizado para acompanhar e localizar o andamento da entrega.

NOTA_FISCAL

NOTA_FISCAL = @ID_NOTA_FISCAL + NUMERO_NF + SERIE + STATUS_NF + DATA_EMISSAO + VALOR_TOTAL + CHAVE_ACESSO

LEITURA: @ID_NOTA_FISCAL identifica exclusivamente a nota fiscal. Os demais atributos registram seus dados fiscais, situação, emissão, valor e chave de acesso.

Atributo Tipo físico sugerido Obrigatório Chave INTERPRETAÇÃO

NUMERO_NF varchar(20) Sim — Número atribuído à nota fiscal para identificação do documento fiscal.
SERIE varchar(10) Sim — Série utilizada para complementar a identificação da nota fiscal.
STATUS_NF varchar(30) Sim — Situação da nota fiscal dentro do processo fiscal.
DATA_EMISSAO date Sim — Data em que a nota fiscal foi emitida.
VALOR_TOTAL decimal(12,2) Sim — Valor monetário total registrado no documento fiscal.
CHAVE_ACESSO varchar(44) Sim — Código utilizado para identificação e consulta da nota fiscal eletrônica.

4. Relacionamentos e interpretação das cardinalidades

Relacionamento Lado A Lado B INTERPRETAÇÃO
FAZ CLIENTE (0,n) PEDIDO (1,n) Um cliente pode estar ligado a zero ou vários pedidos; cada pedido participa da relação conforme a cardinalidade indicada no modelo.
CADASTRA REPRESENTANTE (0,n) CLIENTE (1,n) Um representante pode cadastrar zero ou vários clientes, conforme a cardinalidade do modelo.
GERA PEDIDO (0,1) ENTREGA (1,1) Um pedido pode não gerar ou gerar uma entrega; cada entrega está ligada a exatamente um pedido.
POSSUI PEDIDO (0,n) PRODUTO (1,1) Um pedido pode possuir zero ou vários produtos, conforme a cardinalidade apresentada no modelo.
POSSUI PAGAMENTO (1,1) PEDIDO (0,1) Cada pagamento está ligado a um pedido; um pedido pode não possuir ou possuir um pagamento.
FORNECE FORNECEDOR (0,n) MATERIAL (0,n) Fornecedor e material possuem participação opcional e múltipla na relação.
É FEITO COM MATERIAL (0,n) PRODUTO (1,n) Materiais podem estar associados a vários produtos; produtos participam com um ou vários materiais.
É UTILIZADO MATERIAL (0,n) PRODUÇÃO (1,n) Um material pode participar de várias produções; cada produção utiliza um ou vários materiais.
É PRODUZIDO EM PRODUTO (0,n) PRODUÇÃO (1,1) Um produto pode participar de várias produções; cada produção está associada a um produto.
UTILIZA PRODUÇÃO (1,n) EMBALAGEM (0,n) Uma produção utiliza uma ou várias embalagens; uma embalagem pode participar de zero ou várias produções.

5. Controle de acesso às entidades

O controle de acesso foi ajustado para utilizar somente as entidades existentes no dicionário de dados. Portanto, não são criadas entidades adicionais como USUÁRIO, PERFIL, PERMISSÃO ou RECURSO.

O acesso é descrito diretamente sobre as entidades do modelo: CLIENTE, REPRESENTANTE, PEDIDO, PAGAMENTO, ENTREGA, NOTA_FISCAL, PRODUTO, MATERIAL, FORNECEDOR, PRODUÇÃO e EMBALAGEM. As operações consideradas são Consultar, Inserir, Alterar e Excluir.

LEITURA

Cada entidade possui operações de acesso compatíveis com sua finalidade dentro do processo. Entidades cadastrais, como CLIENTE, REPRESENTANTE, PRODUTO, MATERIAL e FORNECEDOR, admitem manutenção cadastral. Entidades transacionais, como PEDIDO, PAGAMENTO, ENTREGA, NOTA_FISCAL e PRODUÇÃO, possuem acesso voltado ao registro e acompanhamento de suas ocorrências. EMBALAGEM possui manutenção de seus dados cadastrais e utilização no processo de produção.

6. Matriz de operações das entidades

A matriz abaixo consolida o controle de acesso exclusivamente sobre as entidades que fazem parte do dicionário. Não são criados cargos, perfis ou entidades de segurança que não estejam representados no modelo conceitual.

LEITURA

As operações indicam quais ações podem ser realizadas sobre cada entidade: Consultar para leitura dos registros, Inserir para inclusão, Alterar para atualização e Excluir para remoção. A aplicação dessas operações a usuários ou grupos de usuários pode ser definida posteriormente pela regra de negócio ou pela implementação do sistema, sem alterar o dicionário conceitual.
